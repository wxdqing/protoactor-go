identitylookup

这是一个为 Proto.Actor Cluster 定制的持久化身份定位层。它不处理业务 grain，而是协调 ClusterIdentity 到 PID 的查找、激活、校验、失效和回收。

一句话判断

它是“分布式虚拟 actor 路由协调器”，不是“业务 actor 框架”。

  • 负责 identity 到 PID 的持久化映射
  • 防止多个节点并发重复激活同一个 grain
  • 支持 manual kind 的显式生命周期控制
  • 通过 member epoch 识别旧 PID 是否过期

职责定位

StorageIdentityLookup 挂在 Proto.Actor Cluster 的 identity lookup 扩展点上，对外提供 Get、Activate 和 Shutdown。内部真正的决策中心是 Manager。

这套实现的关键设计是：把激活路由信息放到外部存储，用乐观锁或记录锁协调多节点并发，然后只在目标节点本地真正 Spawn grain actor。

Proto.Actor Cluster 适配层 外部存储协同 MemberID + epoch 校验 当前实现仍存在若干高风险问题

生命周期摘要

从使用方角度，可以把这套库理解为下面这 8 个阶段。

1. Setup：把 `StorageIdentityLookup` 注册进 Proto.Actor Cluster，内部创建 `Manager`。
2. Start：Manager 启动 `placementActor`、`manualProxyActor`，并订阅拓扑事件。
3. Topology Learn：通过 `ClusterTopology` 建立 member name 到 epoch 的有效映射。
4. Lookup：查询存储中的 `PID + MemberID` 记录并校验是否可信。
5. Activate：必要时通过锁与远程请求在目标节点完成 Spawn。
6. Serve：业务继续通过 grain client 使用现成 PID。
7. Terminate：本地 grain 结束后广播终止事件，写回 `TerminateTime`。
8. Shutdown：关闭补偿 ticker，Poison 管理 actor，并级联结束子 grain。

代码风险

当前实现的设计方向是对的，但代码状态并不干净。下面是这次 review 中最重要的风险点。

高：导入路径污染

placement_actor.go 仍然引用了不一致的模块路径，属于真实的构建风险。

高：测试未执行

system_id_test.go 中函数名不是 TestXxx，Go 测试框架不会运行它。

中：激活失败后无显式清锁

如果拿锁后选点失败或远程 Spawn 失败，只能等锁超时，形成短时不可用窗口。

中：删除补偿只在内存中

进程退出后，未完成的终止补偿会丢失，记录一致性依赖后续自然覆盖。

建议后续动作

  • 先统一模块导入路径，恢复基础编译。
  • 补最小单测，至少覆盖 `SystemID` 解析和激活锁语义。
  • 为激活失败增加显式解锁或更短回滚路径。
  • 把乱码注释替换成可读说明。
